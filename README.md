# Техники промптинга для преподавателей

Интерактивная лекция: 10 техник, дополнительные приёмы, 14 инфографик, 11 интерактивных блоков и самопроверка из пяти вопросов.

## Публикация через сайт GitHub

1. Распакуйте архив `Prompting_GitHub_Pages.zip` на компьютере.
2. Откройте https://github.com/new и создайте репозиторий, например `prompting-for-teachers`. Выберите **Public**. Это позволяет использовать GitHub Pages на бесплатном тарифе. Нажмите **Create repository**.
3. В пустом репозитории нажмите **uploading an existing file**. Если файлы уже есть, выберите **Add file → Upload files**.
4. Откройте распакованную папку. Перетащите в окно загрузки её содержимое: `index.html`, папку `assets`, `README.md` и `.nojekyll`. Загружайте содержимое, а не внешнюю папку и не ZIP-архив. Файл `index.html` должен оказаться в корне репозитория, рядом с папкой `assets`.
5. Дождитесь окончания загрузки всех файлов, введите сообщение `Публикация лекции` и сохраните их кнопкой **Commit changes** в ветку `main`.
6. Откройте **Settings → Pages**. В разделе **Build and deployment** выберите **Source → Deploy from a branch**. Укажите ветку **main**, папку **/(root)** и нажмите **Save**.
7. Дождитесь завершения публикации. В **Settings → Pages** появится ссылка **Visit site**. Если сайт ещё не готов, проверьте выполнение задачи **pages build and deployment** во вкладке **Actions**.
8. Откройте опубликованную лекцию. Адрес при выбранном имени репозитория будет иметь вид `https://ВАШ-ЛОГИН.github.io/prompting-for-teachers/`. Именно эту ссылку отправляйте слушателям.

## Что лежит в папке

- `index.html` — готовая страница со стилями, сценариями и встроенными интерактивными блоками.
- `assets/` — изображения в исходном качестве.
- `.nojekyll` — служебный файл для публикации готового HTML без обработки Jekyll.
- `README.md` — эта инструкция.

Сборка на GitHub и установка библиотек не требуются. Относительные пути позволяют публиковать лекцию в репозитории с любым названием.

## Проверка после публикации

Откройте несколько изображений на весь экран, раскройте «Текст лекции», переключите интерактивный блок и пройдите самопроверку. В ней должно быть пять вопросов, а после «Пройти заново» — результат `0 / 5`.

Если видна ошибка 404, дождитесь завершения публикации и проверьте, что в настройках выбраны `main` и `/(root)`, а `index.html` находится в корне.

Если отсутствует изображение, проверьте, что папка `assets` загружена целиком и имена файлов не изменены.

## Как обновлять лекцию

После правок загрузите новую подготовленную версию `index.html` и изменённые изображения по тем же путям через **Add file → Upload files**, затем сохраните изменения. GitHub Pages повторно опубликует страницу; ссылка останется прежней.

Для автора: подготовленная версия создаётся скриптом `Docs/prepare_github_pages.py` в рабочем проекте после запуска `Docs/build_site.py`. Сам скрипт и рабочие материалы для публикации не нужны.
